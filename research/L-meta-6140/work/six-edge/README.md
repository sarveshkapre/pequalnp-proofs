# The six-residual-edge plane case

This package concerns the order-three projective plane with six residual incidences, one ordinary top AND at each of the 13 lines, no centreless top, two dirty ANDs, and three exceptional ORs. A residual incidence is a point–line pair whose endpoints never reach opposite ports of an ordinary top through ORs alone.

This follows Amritpal Nijjar’s question about residual edges and reuses the upstream OR-path and circuit-routing lemmas in Myles Li’s eleven-vertex proof. The six-edge circuit translation and certificate replay here concern the order-three plane. [Discussion](https://github.com/open-goat/pequalnp-proofs/discussions/21642#discussioncomment-19908366) · [Upstream routing proof and its credits](https://github.com/open-goat/pequalnp-proofs/pull/14942)

## Lean results

- `case_covered` maps the charged gates of a least top-form circuit to one of the 34 pairs of gate-order and centre-route masks. In a centred circuit a dirty AND must have a later charged reader. An exceptional OR before the first dirty AND adds nothing to a top operand beyond its raw literals.
- `matches_ports` gives the search's two operand forms. An operand is a prior charged wire, or it is the OR of a nonempty set of raw literals and compatible earlier exceptional ORs. The raw set fits in a singleton or in one of the 13 leaves. `residual_card` identifies the encoder's count of missing raw pairs with the circuit's residual count.
- Lean verifies the coordinate relabellings used to fix an incidence or two specified lines, the order change putting raw-only ORs first, the shape of an active first dirty AND, and the test-preserving step that mutes a first dirty AND which stays off on the residual incidences.
- `select_port` and `ordered_ports` choose actual direct reads, literal sets, hosts and promotions for the five charged gates. `GateSchedule.evaluation` proves that these choices reproduce the values of the physical gates in both the original order and a reordered schedule. `GateSchedule.muted_tests` establishes the positive and negative tests for an inactive refinement. `positive_sample_exact`, `negative_sample_edge_free` and `residual_flags_count` check the specific inputs and residual count used by the encoder.
- `schedule_replay_choice` chooses a recorded refinement from the first dirty AND's activity after reordering. It supplies the required coordinate anchor and the shape of an active first AND where the selected refinement uses it.
- `circuit_satisfies_preparation` proves that every circuit in scope selects a recorded key and satisfies the exact encoder's preparation clauses. These clauses require every ordinary leaf to be nonempty, count six missing incidences and fix a residual incidence when the centre mask is empty. Lean also verifies the variable trace for both preparation branches. `audit_eligible` proves the encoder's local checks for a selected promotion or route with nonempty raw support contained in its target.
- `replayInputs` assigns the direct-read, atom, host, promotion and top-route variables for the five charged gates. `replay_reads_earlier` checks the order of every selected read, and `replay_dirty_has_reader` provides a direct-read witness for each dirty AND. `audit_scheduled_gate` checks the emitted AND/OR sample values when both operands have the specified values. `audit_combine_raw`, `audit_port_order` and `audit_first_activity` check the corresponding encoder segments given their operand and activity data.
- `audit_physical_output_tests` checks the top-route selection, eligibility and anchor clauses and all emitted sample test clauses given `ScheduledOutput`. This condition asks for the stage flags, raw support and sample values of the five charged gates. `replay_sample_tests` covers all 52 required incidences and 80 edge-free samples, including the inactive refinements. `physical_centre_presence` supplies a true selector for each set centre-mask bit.
- `buildPort_scheduled` gives the meaning of the exact port builder's return values at either operand of any of the five charged gates. Given the interpreted SAT trace and the earlier stage arrays, the 26 raw entries encode the operand's input support and the 132 value entries encode its behavior on the samples. A direct read copies both tables from an earlier gate. An atom port contributes its own input support and can also read the sample values of eligible earlier ORs. The port refactor reproduces the 95 certificate inputs byte for byte, including their recorded hashes.
- `audit_scheduled_stage_ports` proves that the selected physical ports satisfy every required clause from the two `buildPort` calls and the port-order check at any of the five stages. Exactly one operand mode is selected. An atom mode is nonempty and selects one host that contains its raw inputs. A leaf host contains at least two selected inputs. A selected promotion belongs to atom mode and has nonempty raw support contained in the operand's. The hypotheses are the earlier stage raw-support tables and the checked leaf bank.
- `audit_buildStages` checks both ports, the gate, the ancestor-order clauses, and the first dirty AND's shape and activity across the exact five-stage loop. Appending a stage preserves all earlier entries. The new entry records its gate kind, the 26 raw-input support bits and its values on all 132 samples, with a quiet first dirty AND set to false when the refinement calls for it. `audit_stages_for_output` packages those results with the checked leaf bank and the coordinate anchor for the existing output-test proof.
- `physical_first_shape` and `audit_first_shape` connect the selected refinement to every clause emitted by `checkFirstShape`. In the point-only case neither operand contains a line. In either named-line case the first-stage operand order puts the specified line on the right, and the left operand contains only points, including one outside that line. The other four refinements emit no shape clauses.
- `canonical_order_witness` identifies a strictly earlier dirty AND for each exceptional OR after the first dirty AND in the canonical order. Tracing backwards through OR gates reaches that AND. `port_dirty_source` proves that direct reads and selected intermediate ORs preserve its identity. The five ancestor bits keep this wiring meaning even when the replay forces a gate's sample values to false.
- `circuit_ancestor_order` connects that witness to the SAT clauses. A physical circuit in the six-edge family selects a recorded key and input selectors. Every ancestor-order clause emitted by preparation and the five stages then has a true literal in any assignment that interprets the emitted definitions and constant correctly.

## Circuit exclusion and certificate coverage

The last circuit step is `circuit_to_exact_assignment` in [SixEdgeTranslation.lean](SixEdgeTranslation.lean). It maps any circuit with the assumptions above to one of 95 formulas and gives a satisfying assignment whenever the variable numbering in that formula is valid. The proof covers both operands at all five gates, every output test and both final wire-use checks.

One wiring rule needs a separate argument. Suppose the first dirty AND uses only points. If its signal can reach the centre side of an ordinary top AND through OR gates, select all points and no lines. The signal reaches that side, and the opposite leaf contains a point, so the ordinary top turns on. There is no selected line, hence no selected incidence. This contradicts what the circuit computes. [Centre-exclusion proof](SixEdgeCentreExclusion.lean)

The 95 formulas cover 34 combinations of gate order and centre routing. The tests include all 52 incident point–line pairs and 80 edge-free inputs. Every real circuit in scope must pass these tests, so a contradiction on this sample suffices.

The final theorem, `exclude_six_edges`, takes one finite premise. For each recorded case, `caseChecks` must accept an LRAT proof of contradiction. The function checks the variable numbering and replays the proof against the exact formula built for that same case. The offline driver evaluates this premise for every case. It also compares the Lean-generated formula byte for byte with the independent Python encoder and the SHA-256 in [the original manifest](certificates.json). The large LRAT proofs are regenerated locally. The importable theorem keeps their successful checks as an explicit premise. [Executable checks](SixEdgeJointReplay.lean)

The November 25–26 verification passed a clean 47-module Lean 4.36.0 build. The independent DIMACS replay and the direct Lean check both passed all 95 distinct entries in the original manifest. The standalone kernel also replayed the changed formula generator, centre proof, stage audit, induction, joint checker and final translation. Both final theorems report only `propext`, `Classical.choice` and `Quot.sound`. The unrestricted plane bound remains open.

## Replay

Use Lean 4.36.0 and the upstream checkout at `e6bfe1a56efc768d244627b78f175b18de1acd6f` with its build cache and pinned Mathlib. Keep this directory alongside `work/overlap` so the build can find its earlier plane lemmas.

```sh
python3 -B work/six-edge/check.py /path/to/pequalnp-proofs --lean /path/to/lean
```

Add `--proof-only` to skip CaDiCaL, or `--kernel-replay` for an additional standalone kernel replay. The command uses a temporary build directory and the tools installed alongside Lean.
